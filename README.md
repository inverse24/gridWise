## 📌 Executive Summary

**GridWise LLM** is an enterprise-grade, physics-constrained Smart Grid Optimization and Decision Support System engineered for the **BUP CSE FEST 2026 Preliminary Round**. Modern electrical distribution grids face unprecedented volatility from fluctuating consumer demand, intermittent renewable penetration (solar PV, wind turbines), and localized grid congestion.

GridWise bridges high-performance **mathematical power dispatch optimization** with **state-of-the-art Large Language Model (LLM) explainability** and **deterministic physical safety validation**. Every dispatch directive generated by GridWise is mathematically optimal, physically safe (100% compliant with Kirchhoff’s laws and thermal limits), and accompanied by transparent, audit-ready natural language justifications for human grid dispatchers.

## 🔬 Core Engineering Breakdown

### 1. Section 1: Ingestion, Topology Modeling & State Estimation (section1.py)
* **Dynamic Grid Graph Construction**: Constructs an adjacency-matrix and directed graph model of buses, transformers, transmission feeders, distributed energy resources (DERs), and consumption sinks.
* **Telemetry Normalization**: Ingests raw telemetry payloads (JSON/CSV/SCADA streams), sanitizes sensor dropouts, and computes per-phase active (P) and reactive (Q) power demands.
* **Renewable Forecasting Integration**: Aggregates solar irradiance and wind velocity profiles to calculate instantaneous available generation versus baseline grid demand.
* **Verified by Unit Tests**: test_section1.py rigorously validates topology consistency, feeder capacity calculations, and transformer loading factors under normal and peak stress scenarios.

---

### 2. Section 2: Mathematical Optimization Engine (gridwise_section_02_optimizer.py)
GridWise formulates grid dispatch as a Multi-Objective Constrained Optimization Problem:

min J = sum(C_g * P_g) + sum(C_b * P_b) + sum(W_l * P_shed_l) + lambda * P_loss

#### Subject to Physical & Operational Constraints:
1. **Power Balance (Demand-Supply Equilibrium)**:
   Total Generation + Battery Discharge - Battery Charge + Shedding = Total Demand + Transmission Losses
2. **Generator Ramp Rates & Physical Thresholds**:
   P_min <= P_g <= P_max, ramp rate limits strictly bounded per timestep.
3. **Battery Energy Storage System (BESS) Dynamics**:
   SOC_min <= SOC_b <= SOC_max with round-trip charge/discharge efficiency modeling.
4. **Strict Prioritized Load Shedding Weights (W_l)**:
   * **Priority 1 (Critical)**: Hospitals, Water Treatment, Defense, Emergency Telecom (W_1 = 100,000 — Shedding penalized catastrophically).
   * **Priority 2 (Industrial)**: Continuous Manufacturing, Heavy Machinery (W_2 = 10,000).
   * **Priority 3 (Commercial)**: Retail, Offices, Shopping Districts (W_3 = 1,000).
   * **Priority 4 (Residential)**: Domestic Feeders with rotational equity guarantee (W_4 = 100).

---

### 3. Section 3: Deterministic Safety Validation & Verification (gridwise_section_03_validator.py)
No optimization result or LLM output is ever executed without passing through the Section 3 deterministic validation pipeline:
* **Physics & Circuit Verification**: Validates line ampacity limits (I_ij <= I_max) and voltage deviations (0.95 <= V_i <= 1.05 p.u.).
* **Anti-Starvation Fairness Assurance**: Enforces historical feeder rotation tracking to prevent localized demographic groups from suffering consecutive load-shedding cycles.
* **Schema Contract Enforcement (schemas.py)**: Uses Pydantic v2 strict models for runtime type safety, validating all field bounds, unit identifiers, and numeric tolerances.
* **Local Test Suite (test_section_03_local.py)**: Validates negative test cases (overload injections, malicious boundary values, frequency anomalies) ensuring that illegal schedules are immediately intercepted and flagged with precise diagnostics.

---

### 4. LLM Explainability & Operator CoT (Chain-of-Thought)
* **Natural Language Explanation**: Translates abstract solver decision vectors into plain, actionable operational briefings (e.g., "Substation 4 shed 2.5 MW of Priority 4 residential load to protect Transformer T-02 from a 118% thermal runaway").
* **Root Cause Diagnostics**: Explains why specific generators were throttled or why battery reserves were deployed during sudden solar dropouts.
* **Interactive Operator Querying**: Supports natural language queries from human dispatchers evaluating "what-if" scenarios.

## 🚀 Quick Start Guide

### 1. Local Environment Setup
```bash
git clone https://github.com/your-team/gridWise.git
cd gridWise
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 2. Running Verification & Test Suites
```bash
# Run entire test suite with detailed reporting
pytest -v

# Run Section 1 specific tests
pytest test_section1.py -v

# Run Section 3 local constraint validation suite
python3 test_section_03_local.py
```

### 3. Running with Public Sample Cases
```bash
python3 main.py --input BUP_CSE_FEST_2026_Preli_Public_Sample_Cases.json --output solution.json
```

## 🐳 Docker Deployment

```bash
# Build the production Docker image
docker build -t gridwise-llm:latest .

# Run the containerized test suite
docker run --rm gridwise-llm:latest pytest -v

# Execute against sample data in Docker
docker run --rm -v $(pwd):/app/data gridwise-llm:latest \
  python main.py --input /app/data/BUP_CSE_FEST_2026_Preli_Public_Sample_Cases.json --output /app/data/docker_solution.json
```
